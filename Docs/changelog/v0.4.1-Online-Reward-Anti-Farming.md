# v0.4.1 — Online Reward (Server-Side) + Anti-Farming

**Released:** 2026-07-23  
**Status:** Unreleased (internal build)

## Overview

Moved online reward calculation and distribution to server-side Cloud Code to prevent client-side manipulation. Ratified and corrected reward balance per [[design-doc]] v2 (game-designer review). Implemented comprehensive anti-farming limits at server level (per-day caps, per-rival victory caps, abandonment exclusions).

## Key Changes

### Balance Correction (Design-Doc v2)

**Online Reward Structure — Victory**

| Board Size | Base | Multiplier | Award | Previous (v0.4.0) |
|------------|------|-----------|-------|-------------------|
| 3×3 | 10 | 1.25 | **12** | 10 (1.0×) |
| 6×6 | 20 | 1.25 | **25** | 20 (1.0×) |
| 9×9 | 30 | 1.25 | **37** | 30 (1.0×) |
| 11×11 | 40 | 1.25 | **50** | 40 (1.0×) |

**Other Outcomes**
- Draw (tie): Base × 1.0 (no multiplier)
- Loss: 0 (no reward)
- Victory by abandonment: 0 (anti-farming enforcement)

**Previous Implementation (v0.4.0)**
- Provisional base × 1.0 with loss floor of 1P (2/4/6/8 minimum), ratified as incorrect
- Calculation was client-side (now moved server-side)

### Architecture: Server-Side Implementation

**Cloud Code Module Changes**

New files in `CloudCode~/TicTacToeModule`:

1. **OnlineRewardCalculator.cs** (new)
   - Derives from `TTTXO.Core.RewardCalculator` (no duplication of reward table)
   - Applies online-specific multiplier (1.25× for victory, 1.0× for draw)
   - Enforces abandonment exclusion

2. **OnlineRewardStore.cs** (new)
   - Manages Cloud Save Player Data entries:
     - `currency` — Total soft currency balance
     - `daily_ledger` — Today's earned amount (UTC server date)
     - `rival_ledger` — Victory count per rival playerId (24h window)
   - Checks caps before awarding:
     - **Daily sub-cap:** 200 online soft currency per UTC day
     - **Global cap:** 300 soft currency per UTC day (includes offline; offline-only transactions bypass server audit)
     - **Per-rival cap:** Max 3 paid victories per rival in 24h; 4th+ vs same playerId = 0
     - **Abandonment cap:** Victory by opponent abandonment = 0 (always)

3. **Modified Files**
   - `MatchFunctions.cs` — `PlayMove()` now calls OnlineRewardCalculator at terminal move; `GetMatchState()` resolves abandonment and emits 0 reward
   - `Dtos.cs` — New field: `MatchStateDto.AwardedSoftCurrency` (additive, nullable, per-turn)
   - `MatchStateStore.cs` — Stores awarded amount in match state (audit trail)

**Client-Side Changes**

- Remove provisional reward block in `GameScreenController` (comment: "pending game-designer ratification" + RewardCalculator.SoftCurrencyFor with Medium difficulty)
- `MatchStateDto.AwardedSoftCurrency` displayed to player (server-sourced value only)
- No client-side reward calculation (server is source of truth)

### Analytics

- Existing `soft_currency_earned` event now also emits `source="online_quickmatch"` when applicable
- No new event registration required (existing infrastructure reused)
- Ledger audit available in Cloud Save per playerId

### Known Limitations (Documented)

**Offline Rewards Not Unified**

- Global 300/day cap only audits online (server-side) rewards
- Offline local play (1P vs AI, local 2P) rewards remain client-stored (no audit)
- **Reason:** Offline rewards never leave device; unifying requires migrating offline issuance to Cloud Code
- **Future Work:** Consolidate offline and online reward flow under server audit (M4.2+)

### User-Facing Impact

**Patch Notes Summary**
- Online match victories now reward slightly more than before (base × 1.25 instead of base × 1.0)
- Losing online matches yields no reward (no loss floor)
- Limits enforced:
  - 200 online soft currency per day (server-enforced)
  - Max 3 paid wins per rival every 24 hours (prevents farming same opponent)
  - Winning by opponent abandonment yields 0 (anti-farming)

### Deployment

**Requirements**
- Re-deploy `TicTacToeModule.ccmr` to Cloud Code (user already performed; not blocking)
- No new Remote Config keys (caps are code constants, not configurable)
- Protocol: `MatchStateDto` has new optional field (backward compatible, no major version bump)
