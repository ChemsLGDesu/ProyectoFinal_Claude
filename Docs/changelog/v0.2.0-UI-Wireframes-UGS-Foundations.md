# v0.2.0 — UI Wireframes + UGS Foundations

**Released:** 2026-07-23  
**Status:** Unreleased (internal build)

## Overview

Completion of **Milestone 1.5 (UI Redesign)** and **Milestone 2 (UGS Integration Foundations)** — redesigned UI layer following approved wireframes, new player-facing screens (Profile, Match History, Settings, Store), and foundational cloud integration with Unity Gaming Services (offline-first, with graceful fallback).

## Key Deliverables

### UI Redesign (Milestone 1.5)

**6 Core Screens Rebuilt**
- All playable screens redesigned according to approved wireframes ([[06-Wireframes-UI]])
- Visual identity defined in new aesthetic guide ([[07-Estetica-UI]]): dark palette with neon accents (X cyan #35E6C6, O violet #7C5CFF)
- Dynamic theme applied consistently across all screens

**New Player-Facing Screens**
- **Profile** — Player identity, "Name#1234" format (allocated server-side)
- **Match History** — Last 50 local matches stored in PlayerPrefs with timestamps, opponent type, result
- **Settings** — Language selector (active, no-op but UI ready), Sound/Music volume sliders (persistent, no audio playback engine yet)
- **Store** — Stub "Coming soon" placeholder for future cosmetics/battle pass
- **Online Status Card** — Visible in Home with "Soon" tag (no online connectivity yet)

**Shared UI Components**
- Confirmation overlay — Reusable modal for destructive actions
- Toast notifications — In-game feedback (e.g., "Account deleted")
- "Delete my data" flow — Local-only, deletes PlayerPrefs (match history + wallet)
- "Delete account & data" flow — UI only; server-side logic pending UGS Dashboard activation

**No Gameplay Changes**
- Core game mechanics unchanged (M1 rules, AI, board logic fully intact)
- Solo new PlayerPrefs key: `TTTXO_MatchHistory` (JSON array of 50 most recent matches)
- Sound/Music volumes persisted as `TTTXO_SoundVolume` and `TTTXO_MusicVolume` (no audio engine integration yet)

### UGS Foundations (Milestone 2)

**Authentication Module**
- Anonymous sign-in at app launch
- Player nickname allocation via server API: "Name#1234" format (random 4-digit suffix)
- Home screen displays current player name
- Silent fallback to local-only if network unavailable

**Analytics Integration**
- Defensive wrapper around GameAnalytics (graceful null if not available)
- 4 tracked events:
  - `match_started` — Board size selected, difficulty chosen
  - `match_finished` — Result (win/loss/draw), elapsed time
  - `board_size_selected` — User picks 3×3, 6×6, 9×9, 11×11
  - `soft_currency_earned` — Amount, source (victory, multiplier applied)
- No telemetry payload exposed to client (server-side processing)

**Remote Config (Config-as-Code)**
- `Assets/RemoteConfig/GameConfig.rc` — YAML-based configuration
  - `BOARD_CONFIGS` — Board size → k-value, reward base (mirrors design-doc)
  - `AI_DIFFICULTY_PARAMS` — Easy/Medium/Hard/Adaptive parameters (pWin, pBlock, blunder rates)
- Zero runtime loading; all configs baked at build time
- Fallback to design-doc hardcoded values if config file missing

**Cloud Save (Best-Effort Mirror)**
- Periodic sync of:
  - Soft currency wallet (PlayerPrefs → Cloud)
  - Match history (last 50 local matches)
  - Adaptive AI levels per board size
- Client-authoritative: local state takes precedence if conflict
- Silent skip if network unavailable (no error UI)

**Cloud Code Module**
- `CloudCode~/TicTacToeModule/` — Server-side C# functions
  - `GetGameConfig()` — Returns board/AI configs (for future online validation)
  - `CreateMatch()` — Reserve match ID, initialize state
  - `PlayMove(matchId, cellIndex)` — Server validation + AI move (reuses TTTXO.Core)
  - `GetMatchState(matchId)` — Fetch current board state
  - `GetAiMove(matchId, boardState, difficulty)` — Execute AI strategy (reuses TTTXO.Core)
- **No code duplication:** All functions delegate to TTTXO.Core types (BoardState, AiPlayer, RulesEngine)
- No online matchmaking or PvP yet (foundations only)

**Package Versions**
- `com.unity.services.core` 1.18.0
- `com.unity.services.authentication` 3.7.3
- `com.unity.services.cloudcode` 2.10.4
- `com.unity.services.cloudsave` 3.4.1
- `com.unity.services.analytics` 6.3.0
- `com.unity.services.remote-config` 4.2.5
- `com.unity.deployment` 1.7.2

**Splash Screen UX**
- Initialization sequence: check UGS services, log auth status
- Generic error state with "Retry" button if any service fails
- Timeout failover to local-only play (60s max wait)

**Game Protocol**
- `GameProtocol.Version` handshake (warning logged if mismatch, non-fatal)
- All client-server messages versioned for future compatibility

**100% Offline Playable**
- Complete local game without any UGS connection
- All M1 features (4 difficulties, 4 board sizes, soft currency, 2P local) work standalone
- Zero hard dependency on cloud (all features degrade gracefully)

## Next Steps (User Action Required)

To activate UGS services in production:

1. **Enable Services in Dashboard:**
   - Log in to [Unity Dashboard](https://dashboard.unity.com/)
   - Enable Authentication, Analytics, Remote Config, Cloud Save, Cloud Code for this project

2. **Register Events in Event Manager:**
   - Add 4 custom events: `match_started`, `match_finished`, `board_size_selected`, `soft_currency_earned`
   - Map to Analytics dashboard for monitoring

3. **Deploy Cloud Code:**
   - Window → Deployment → Deploy `CloudCode~/TicTacToeModule/`
   - Verify deployment status in Dashboard

4. **QA Verification:**
   - Test offline mode thoroughly (no network, kill app mid-sync)
   - Verify local fallback behavior (e.g., login fails → still playable)
   - Confirm wallet sync on reconnect
