# v0.4.0 — Online Quickmatch + Wire (Milestone 4)

**Released:** 2026-07-23  
**Status:** Unreleased (internal build)

## Overview

Full multiplayer matchmaking and real-time synchronization via Wire. Players can create online matches, search for opponents by board size, and play in real-time with push notifications. Includes defensive grid fallback and navigation stack fixes from prior unreleased build.

## Key Deliverables

### Multiplayer Services Integration

**Package Versions**
- `com.unity.services.multiplayer` 2.2.3 (bundles Wire SDK 1.4.4)
  - Replaces deprecated `com.unity.services.matchmaker` package (unified in Unity 6)

### Matchmaker Configuration (Config-as-Code)

**Files**
- `Assets/Matchmaker/QuickmatchQueue.mmq` — Queue definition
- `Assets/Matchmaker/MatchmakerEnvironmentConfig.mme` — Environment configuration

**Configuration Details**
| Setting | Value | Purpose |
|---------|-------|---------|
| Pool | `quickmatch` | No ranking; no skill-based matching |
| Backfill | `board_size` attribute | Match players by board size preference |
| Hosting | MatchId (serverless) | No dedicated server required |
| Ticket TTL | 180 seconds | Max ticket lifetime before expiration |

### Cloud Code Module Enhancements

**CreateMatch() — Idempotent Handoff**

Receives Matchmaker ticket and executes two-step match creation:

1. **Ticket Verification** (best-effort)
   - Calls admin endpoint to resolve ticket fields
   - Degrades to warning on 401 (service-account limitations)
   - Method: `TryVerifyTicketResolvesToHandoffAsync()` — clarifies non-blocking behavior

2. **Roster Resolution**
   - Extracts playerIds from ticket metadata
   - Limitation: Matchmaker SDK does not expose full roster; workaround via ticket fields

3. **MatchId Allocation & Initialization**
   - Creates unique MatchId in game state
   - Initializes empty board
   - Stores X/O assignments

4. **Deterministic Player Assignment**
   - Sorts playerIds lexicographically
   - First → X (cross); Second → O (circle)
   - Deterministic across client retries (prevents assignment conflicts)

**PlayMove() — Online Validation**

- Verifies requesting playerId matches current turn owner
- Rejects invalid moves with `InvalidReason: "Not this player's turn"`
- Publishes move event via `IPushClient` (Wire) to opponent (real-time notification)

**GetMatchState() — Reactive Abandonment**

- Detects inactivity from both players
- Checks duration against `MATCHMAKING_CONFIG.abandonTimeoutMinutes` (Remote Config)
- Default: 3 minutes
- Marks match abandoned if player exceeds threshold
- Opponent can claim forfeit win

### Client-Side Matchmaking

**MatchmakingService** (`Assets/Scripts/Game/Services/MatchmakingService.cs`)

Manages ticket lifecycle:

```
CreateTicket() 
  ↓
PollTicketStatus() (async, backoff loop)
  ↓
[Matched] → Launch OnlineMatchService
[Cancelled] → Fallback to AI mode
```

- Configurable polling backoff via Remote Config
- Graceful cleanup: `CancelTicket()` triggered on `OnApplicationPause`

**OnlineMatchService** (`Assets/Scripts/Game/Services/OnlineMatchService.cs`)

Real-time synchronization:

| State | Meaning | Transitions |
|-------|---------|------------|
| `Connecting` | Subscribing to Wire | → `Subscribed` (success) / `Offline` (fail) |
| `Subscribed` | Active Wire connection | ← receive push → re-fetch `GetMatchState()` |
| `Offline` | Network lost | Fallback polling every 10s |

**Push + Polling Strategy**
- Wire push is primary (real-time)
- Fallback polling every 10 seconds (network resilience)
- Hybrid approach ensures no move loss under poor connectivity

### UI Changes

**Matchmaking Screen** (`MatchmakingScreenController`)

- Spinner animation (searching for opponent)
- Elapsed time counter
- Cancel button (calls `CancelTicket()` on cleanup)
- Fallback link: "Play vs AI" if wait exceeds `MATCHMAKING_CONFIG.waitCeilingSeconds` (default: 45s)
  - **Note:** Fallback not in wireframe 5; documented as design deviation
  - Improves UX by preventing indefinite wait

**Game Screen (Online)**

- New Wire status chip (displays connection state: Connecting/Subscribed/Offline)
- Polling fallback every 10 seconds (independent of Wire subscription)
- Move validation always on server (no client-side prediction)

**Mode Select Menu**

- Quickmatch (fully enabled)
- Ranked (placeholder UI, "Soon" label; no logic yet)

### Analytics Events

**New Events Registered in Event Manager**

- `matchmaking_wait_time`
  - Fired when: Ticket successfully matched
  - Attributes:
    - `+seconds` (duration from CreateTicket to Match)
    - `board_size` (3, 6, 9, 11)
    - `matched` (bool, true for matched; false for cancellations)

- `matchmaking_cancelled`
  - Fired when: Player cancels search or timeout
  - Attributes:
    - `+reason` (e.g., "timeout", "user_click", "app_pause")

### Remote Config Expansion

**BOARD_CONFIGS**
- All 4 sizes now include `"online_quickmatch"` flag (true if available online)
- Defensive fallback: if flag missing, all sizes are available for online selection

**New Key: MATCHMAKING_CONFIG**

```yaml
abandonTimeoutMinutes: 3         # Inactivity threshold before match is marked abandoned
waitCeilingSeconds: 45            # Max wait before showing "Play vs AI" fallback
ticketTtlSeconds: 180             # Ticket lifetime (should match Matchmaker config)
```

### Rewards (Online)

- **Base multiplier:** 1.0× (same as local AI play)
- **Status:** Provisional, pending game-designer ratification
- **Adjustment criteria:** Engagement metrics and win-rate distribution

## Bug Fixes (Integrated from Prior Build)

### Navigation Loop (Profile ↔ Store)

**Problem:** `ScreenRouter` maintained only a single "previous screen" variable. This caused:
- Profile → Store → back → back → loops between the two forever
- Impossible to escape via back button

**Fix:** Replaced single-reference with proper back stack
- `Show(screenId)` — Pushes screenId onto stack
- `GoBack()` — Pops stack and navigates
- `Home` — Clears entire stack (breaks loop)

**Files:** `Assets/Scripts/Game/UI/ScreenRouter.cs`

### Cloud Code Build Failure

**Problem:** Missing `Microsoft.Extensions.Logging.Abstractions` NuGet package.
- `ILogger<T>` interface failed to compile in TicTacToeModule

**Fix:** Added NuGet reference to project file

**Also Fixed:** Obsolete API call
- Replaced `GameApiClient.Create()` with `config.AddGameApiClient()` (current pattern)

**Files:** `CloudCode~/TicTacToeModule/`

### Cloud Code Deployment Failure

**Problem:** Deployment window reported "Could not find a Publish Profile" error
- Without a folder publish profile, `Window → Deployment` would fail

**Fix:** Added folder publish profile
- File: `Properties/PublishProfiles/FolderProfile.pubxml`
- Enables deployment to local folder or cloud storage

### Empty Board Grid (Online)

**Problem:** BoardSelect sometimes showed empty grid when Remote Config online settings were incomplete

**Fixes:**
1. Defensive fallback: if Remote Config omits online board sizes, fall back to all sizes (never empty)
2. Fixed font-rendering in `GameConfig.rc` (no more character clipping)

**Files:** `Assets/Scripts/Game/UI/Screens/BoardSelect.cs`

### CreateMatch 401 Unauthorized

**Problem:** Matchmaker ticket verification endpoint requires Matchmaker Admin role.
- Without proper service account, requests returned 401
- Was blocking match creation

**Fix:** Degraded to warning-level logging
- Best-effort verification (non-blocking)
- Log includes note: "Full enforcement requires service account with Matchmaker Admin role"
- Method renamed to `TryVerifyTicketResolvesToHandoffAsync()` to clarify intent

**Implication:** Tickets are still processed; operator can optionally validate externally if needed

**Files:** `CloudCode~/TicTacToeModule/CreateMatch()`

## Known Limitations & Future Work

**Ranked Mode** (M5+)
- UI placeholder only; "Soon" label
- No matchmaking logic or ranking system yet
- Planned for next iteration

**Dedicated Servers** (M4.1+)
- All matches use serverless hosting (MatchId-based)
- Dedicated server support planned if scaling demands require

**Turnbased Fairness** (Design TODO)
- First player (X) always assigned lexicographically
- No random coin-flip for X/O swap
- Impact on win-rate distribution TBD; pending game-designer review

**Reconnection** (M4.1+)
- If player disconnects mid-match, no auto-reconnect UI
- Player must re-enter via ticket recovery flow
- Planned: persistent session recovery with grace period

**Cross-Region Routing** (M4.1+)
- Wire defaults to closest regional endpoint (Multiplay automatic)
- No explicit latency-aware region selection in client
- Latency optimization pending usage metrics
