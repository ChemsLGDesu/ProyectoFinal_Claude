# v0.4.2 — Pre-Ranked Technical Debt: Hard Ticket Verification + Proactive Abandonment Sweep

**Release Date:** 2026-07-23  
**Status:** Internal build

## Overview

Closes two architecture-critical items marked for completion before Ranked (Milestone 5):

1. **Hard ticket verification** — Matchmaker verification elevated from best-effort logging to blocking validation
2. **Proactive abandoned match resolution** — Complements reactive fallback; sweeps matches left hanging when both players abandon

Both items unblock the Ranked matchmaking pipeline and ensure player progression fairness (MMR, rewards).

## Matchmaker Ticket Verification: Bug Fix → Blocker

### Root Cause (Discovered)

Not an SDK limitation or permission issue — a **parameter order bug**.

Real signature (from `Com.Unity.Services.CloudCode.Apis` 0.0.26 assembly):

```csharp
GetTicketStatusAsync(IExecutionContext, string accessToken, string id, string impersonatedUserId = null, CancellationToken = default)
```

**Previous Implementation Bug:**
- Passed `context.ProjectId` (not a token) → `accessToken` position
- Passed `context.EnvironmentId` (not ticket ID) → `id` position
- Result: never looked up actual ticket; always 401 Unauthorized

### Fix

- Use `context.ServiceToken` and `ticketId` in correct positions (same pattern as `MatchStateStore`, `OnlineRewardStore`)
- `VerifyTicketResolvesToHandoffAsync` (renamed from `TryVerifyTicketResolvesToHandoffAsync`) — now throws on any failure
- `CreateMatch()` rejects match if ticket cannot be verified (strict, not degraded)
- **No new service account roles required** — Matchmaker under "UGS Client APIs", supported by Service Token

### Caveat

Not validated against live environment; module compiles, ready for development testing before production promotion.

## Proactive Abandoned Match Resolution

### New Components

**`MatchIndexStore.cs`** — Cloud Save–backed registry of active online matches
- Partitioned by UTC date: `active-matches-{yyyy-MM-dd}`
- Prevents unbounded growth; old partitions safe to prune
- Enrollment: when 2-player roster completes
- Removal: on all termination paths (PlayMove terminal, reactive abandonment, proactive sweep)

**`SweepAbandonedMatches()` (Cloud Code function)**
- Scans up to 3 daily partitions
- Re-validates each match against live state (does not trust index alone)
- Idempotent and tolerant of parallel resolution (reactive fallback, manual play, other sweeps)
- Hard caps: 200 matches per execution, 500 lookback, 3-day window
- Cron: every 5 minutes (config-as-code: `Assets/Triggers/SweepAbandonedMatches.tr`, `SweepAbandonedMatchesSchedule.sched`)

### Design Decision: Both Abandon → Draw

When both players remain inactive beyond `MATCHMAKING_CONFIG.abandonTimeoutMinutes`:

- Match resolves as **draw (no winner)**
- Reason: Neither player "survives" to claim victory; random winner would bias MMR and reward abandonment
- Reward: 0 for both (consistent with all abandonment scenarios)
- Field: `MatchStateRecord.BothPlayersAbandoned` (new, optional, backward compatible)

### Trigger Deployment

Package `com.unity.services.deployment` 1.7.2 does not expose Triggers/Scheduler in `Window → Deployment`.

**Workaround:** Deploy via UGS CLI

```bash
ugs deploy
```

Documented in module README. Triggers remain manually invocable via Cloud Code console until automatic deployment is ready.

### Alternative Evaluated & Deferred

**Cloud Save Query/Index API** — Would enable filtered match lookup without scanning all partitions.

- **Why not:** Requires index provisioning outside deployment flow; cannot be verified without live environment access
- **Future:** Can optimize post-Ranked (M5.1+); current linear-scan is safe and idempotent
